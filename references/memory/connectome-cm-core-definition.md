**核心=2 件**：①数据格式（知识资产=六类词表+信封字段[类型/触发条件/权威性/外流等级/版本]；运行数据=开放短清单；需求声明=插件接入钥匙）；②注入方式（五语义×机制×降级规则+升级槽）。**四铁律**：镣铐原则（不承诺平台口子外能力，可降级到粘贴包保底）；时空双通用（栗子定：每次更新过空间关[全平台适配器可用]+时间关[存量资产不失效]）；zero-config（CM 本体无参数）；不添乱（CM 给插件的约束⊆平台已有约束）。**CM 本体=冻结层+受控扩展层，无自由层**（加不毁改才毁；防越改越烂三规则=加法优先[CB-S16]/外部锚[Huang 2023]/冻结层走单向升版[宪法§六]）。**插件六件套**：原料/提取器（被目标类型拉动）/格式选型/注入选型（声明式不写代码）/验证执行/治理+可选循环。**反馈系统=优化插件与资产，非 CM 本体**；蒸馏产物三类全落现有词表（元认知标签/版本修订工单/元教训）≈通用化 CB 教训编译器；效果数据格式进核心、误差判据库出核心（栗子裁，ZCode 两轮说服失败后认输）。承载力检验已过项目管理+反馈系统两样本（六类五语义零击穿）。

**六线并行制 v2**（栗子批准，ZCode 代建同步 09-03）：A 类型与资产格式（试装常态化）/B 接入与演进（**①manifest=B-v4 C21 ②版本迁移决策表=B-v5 C22 已交付冻结并流转设计线（09-03 ZCode，C18 开放点 §七.2/§七.3 研究输入首答）**；Q2.8/粒度/边界/自我优化理论挂起待插件立项）/C 注入（①穷尽论证②Q3.5 多资产协同③触发可靠性）/D H0 本职保留（插件侧度量挂起）/E 原料格式清单/V 承载力检验（新设，铁律=只检验不设计，第一刀 HC；V-v1=C20 装不下两缺口→#012 信封字段扩容归 A 线）。开放点四现状：多资产协同（未动，第一撞墙点）/需求声明形状+版本迁移机制（研究输入首答=B-v4/B-v5，细形状归设计线）/NC 遵循度可测性（未动）。

**栗子方法论收获**：①不变量分析法（六需求并排逐环节找不变量=核心，变者=插件）；②分线第一理由=并行推进，每独立课题一线；③插件=CM 的用户/需求方——用需求**检验**核心（装不下→证据回流升版），**不是**按需求设计核心；④结论必须带证明等级，他的直觉质疑转成可检验流程。相关：[[connectome-c-line-c-v1]]、[[chestnut-evidence-grading-feedback]]

**09-06 深夜·触发条件层级校正（栗子裁，#021 立案）**：触发方式不是资产自带的抽象属性，**由注入机制能力决定**——有 hook 才能把 agent 动作当触发，有检索组件才有语义命中，CM 本体做不了语义命中（没索引没向量库），全都没有→粘贴包人保底。正确分层：信封存**条件声明**（何时该在场，平台无关）→ 机制决定**怎么执行**（能力矩阵+降级）＝镣铐原则在字段层的展开，与 C-v2 强制力谱系/#017 通道预绑定/#013 按卡配路同脉。件一「在场条件声明」方向被印证但缺绑定层不完整；#014 取值空间的正确推导素材=机制能力空间。导图触发条件节点已按此重写（能力矩阵+语义命中定位+缺陷首位=声明机制没绑）。


**09-06 深夜·v1 定死裁定（栗子，#022）**：第一版 CM 核心只做一套**固定**注入机制——无降级链、无升级槽（后版可能做）；触发方式闭集由机制推导；**CM 没有的组件不得出现在 CM 需求里**（检索/RAG 类即此）。ZCode 草案待终审：v1 机制闭集四样=同步钩子/规则装载(含路径惰性)/工具注册/权限闸（C-v2 已证实平台真实存在）；v1 触发条件闭集三样=常驻在场/路径命中/事件命中（事件谓词钩子内可做关键词匹配，不需检索）；砍出 v1=降级链/升级槽/语义命中/到点触发；粘贴包降为保底事实（镣铐原则保留）。后果：C 按需知识 v1 走路径惰性+事件钩子不走检索；件一四取值收敛为三取值。导图触发条件/注入方式节点已按此重写。


**09-06 深夜·交集推导原则（栗子修订 #022，#023）**：v1 设计总原则=**按最通用最一致设计——盘点几乎所有 agent 都有的功能，围绕交集定触发方式与接入方式**。ZCode 前稿两处被纠：①到点触发被错砍（定时任务大部分 agent 都有——本机 ZCode cron/GitTok 04:00 链即活例；错因=盘点轴只看会话内钩子事件集，没看宿主通用能力面）；②钩子从核心闭集移出（部分 agent 才有，不进核心承诺）。修订草案待终审：接入交集闭集=约定文件装载/定时任务/工具注册MCP/权限闸；触发交集闭集=常驻在场/到点触发/动作发生；移出交集=事件钩子/路径惰性/语义检索；C 按需知识 v1 走法=常驻指令指路+agent 自取文件（读文件人人有，不需检索）；强制力让步（交集内硬约束=权限闸级，钩子处增强）待栗子确认。普遍性标注=归纳待证，C 线立项宿主通用能力面系统盘点（扩 C-v2 轴）。


**09-06 深夜·v1 接入闭集终裁（栗子，#024）**：钩子回核心（「要不然基本啥都干不了」——钩子是唯一可编程的事件→自动执行通道，其余皆被动）；约定文件/定时任务/工具注册/权限闸四样栗子确认「肯定都有」；**交集口径落死=按 CM 目标平台取交集**（钩子在目标平台收敛同构=C-v2 已证）；**v1 接入闭集五样**=钩子/约定文件装载/定时任务/工具注册/权限闸，**触发闭集三样**=常驻在场/到点触发/动作发生（钩子拦+权限闸审）；路径惰性规则出核（栗子听不懂这名字——术语不通顺不配进核心设计；其本体=Claude Code 规则文件碰到路径才装载），交集外仅剩它与语义检索。教学教训：跟栗子讨论设计禁用平台黑话裸奔（路径惰性规则即实锤），机制名必须带一句白话机制。
