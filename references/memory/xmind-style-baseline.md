**内容组织方式（栗子的说话/做图习惯，2026-08-19 二次解析确认）**：
- **零 notes / 零 labels / 零 markers**——不用注释、不用标签、不用标记，备注内容一律压成短标题节点（或删去），不让解释性文字进图
- **几乎不写长句**：节点标题以 2-7 字短语为主（名词短语/动宾/两字词），最长一句通常是根口号（例「We shall never surrender.」）；深语义用多层级拆节点表达，不靠长标题或备注
- 分类式命名习惯：两字抽象分类（主线/支线）、「××自由」「××线」式词缀
- 层级：样例图最深 4 层、每层 2-5 个节点——这是**样例观察值，不是栗子定的硬性标准**（栗子 2026-08-19 澄清「层≤4 我没说过」）；深度由内容需要决定，全景细节图做到 6 层亦被接受，只有在真显得挤时才压缩
- 状态标记（如「尚未拍板」）用最简短形式，不附加解释
- **禁解释符号（2026-08-19 第三次反馈补充）**：标题一律不出现「—— / ： / · / →」等解释性符号——需要解释说明就开一个下级主题，符号本身不允许出现在标题里
- **禁标签/注释类元素（同上）**：任何 callout、labels、notes、markers 等标签/注释/浮签类元素都不允许出现在交付图里；该语义若必须呈现（如「尚未拍板」）做成一个正常的主题节点
- **本源之树项目状态（同上）**：SYS-0818-01 的产出「本源之树.xmind」已被栗子自建图 `D:/AI/MD/We shall never surrender..xmind` 正式替代，ZCode 不再产出本源之树文件（已有文件保留未删，处置权归栗子）

**复刻方法（已验证的可靠流程）**：不要用 CLI 主题参数拼（拼不全，subTopic/CJK/tapered/root.extensions 等细节会漏）。正确做法=**以样例 xmind 为模板**：解包 → 改 content.json（仅换 rootTopic.title/notes/children.attached/children.callout，rootTopic.extensions 的 right-number 改成新分支数，保留 theme/style/sheet/zones/extensions/metadata 全部原样）**09-04 增补方向机器防线**：构建脚本必须自动设 right-number=一级分支数，靠人记必翻车——C18 试验图 8 个一级分支只带默认值 3，超出的 5 支跑左边被栗子抓到；两个构建脚本已内置该自动防线。→ 重打包（content.json+metadata.json+manifest.json 三个文件）→ `xmind validate` 0 错 → 桌面 Xmind 打开 + PrintWindow/OCR 验证渲染。内容侧**同步应用内容组织方式**：无 notes/labels/markers、长句压缩为 2-7 字短语再入树。

**坑**：① content.json 顶层是 **list**（sheets 数组），dump 时忘包 [] 会崩 CLI；② 不要带模板的 `Thumbnails/`（是旧图缩略图，manifest 同步去掉）；③ `content.xml` 是旧版遗留占位警告，与内容无关，可丢弃；④ 全局装官方 `@xmindltd/xmind-cli`（v0.2.3，npm 全局），登录 `xmind auth login cn`（浏览器授权只能栗子点）；⑤ CLI 的 `layout/theme` 子命令管不了根结构方向，方向必须写 rootTopic.extensions；⑥ 同路径文件被 Xmind 开着时覆盖重开=旧渲染缓存+「已编辑」标记，验证要用副本文件名+taskkill 干净重启；⑦ 无头验证渲染靠 PowerShell PrintWindow+Windows OCR（xwin 窗口抓取避 GPU 合成），CopyFromScreen 会被前台窗口遮挡。

**栗子导图标准全集（2026-09-04 定稿，强制，任何导图任务开工前必读本节+[[xmind-cli-local-generation]]）**：
- **折叠规则（09-04 二次订正+升级）**：折叠键=topic 上 **`"branch": "folded"`**（模型名 branchState；沉淀早在 [[xmind-cli-local-generation]] 08-19 就有，agent 当晚未查记忆自造 `"folded": true` 写错=图像元素属性，栗子打开无折叠实锤返工——**教训：动手前先 grep 记忆目录**）。折叠深度按**递归多层预算算法**：子树预算 B（默认 50，按图可调）；从根开始逐层累计连带标题数，子树总规模超 B→在其内部找最大可见层，该层有子节点的节点标 `branch:"folded"`；**被折叠节点自身子树再超标→递归嵌套预置折叠（多层折叠）**，保证任何一次展开的单屏不超预算、同级总体宽度不失控。层多主题少→可展到四五级以下；层少主题多→第三级就折叠（栗子原话精神）。**单链不折叠（09-04 晚栗子补）**：展开只多一条线不加宽度的节点（单孩子链）放行不折——折叠标记沿单链下推，只打在「展开会变宽」的分叉节点（≥2 孩子）上。
- **深度规则（09-04 定，晚间接栗子四条批评加码）**：细分到**无可再细分**才停——叶子必须是原子事实（具体数字/名单/取值/实例/机制），概括性主题（如「五字段」「R1至R5」）下面必须继续列全成员或取值，不许停在概括层。**信息量以资产冻结版实际内容为准（登记表逐行+原文），不做记忆压缩**；**每个原子须自解释**（脱离父节点也读得懂）；**问题一律挂所属部件名下**（如 #012 挂信封状态缺口、#002 挂进料资格），不许单设「问题」类目破坏同级同轴。素材不确定的不编造（同延伸版纪律：无素材留白）。09-04 晚栗子判 v4「信息量/原子化/可读性/逻辑性」四不合格→全面重写 v5（506 节点/329 叶/81 折叠点）过关形态。
- **分支自由布局**：sheet 级属性 `"topicPositioning": "free"`（键名从他的 Xmind 本体 app.asar 实测：组件 main-branch-free-positioning-enabled；仅 unbalanced/balanced map 结构支持）；值按模板 kebab 小写惯例（同 `topicOverlapping: "overlap"`），若打开后开关未生效，格式面板手动开一次即可。
- **全右侧真源**：sheet 级 extensions 的 skeleton（`centralTopic: org.xmind.ui.map.clockwise` + `mainTopic: org.xmind.ui.logic.right`）是渲染层方向真源，rootTopic.extensions（right-number）并用；structureClass 保持 `org.xmind.ui.map.unbalanced`。
- **格式真数据**：新版 Xmind 包内 **content.json 才是真数据**，content.xml 只是「请用新版打开」多语言占位警告页——只改 xml 不改 json=白改（09-04 实测翻车一次）。
- **内容结构法（09-04 定，同日晚栗子修正适用范围）**：「第一级=全景主题+分类主题」**只是可选模式之一（CM 图采用），不是普适规则**——其他导图按项目本性选分类轴（流程/组成/并列皆可）；每级兄弟必须同一把分类刀（穷尽+互斥）；环节名用项目正名不用自造比喻词；细节按环节归属，问题挂所属部件名下（20 条问题全挂靠，不许单设「问题」类目）。
- **标题字数（09-04 深夜最终版）**：**2-7 字铁律不动摇**——原子化靠拆深不靠加长，标题说不清就继续开子节点；节点多不是问题（递归折叠兜底）。**禁标点**：逗号、顿号、句号、叹号、问号全部进 BANNED（长句拆成节点，不许标题内带标点连写）。**排比警告**：同级 ≥4 个 ≥7 字的同长句式标题打回强制改写（短枚举名单如六类型名不受限）。曾短暂放宽 2-9 又被栗子收回（「看着很难受，太臃肿」）。`check_titles` 四道机器检查全过才许出图：禁用符/字数 2-7/伞节点/排比。
- **关系线（09-04 试验后否决）**：跨支因果曾试 7 条 XMind 联系线（键=sheet 级 `relationships`，元素=`{id, class:"relationship", end1Id, end2Id, title}`，端点缺失会被静默丢弃）——**栗子判「看着很乱」，标准=不用联系线**；键位留档备查。
- **环节导览（09-04 定）**：流程型图的环节名加序号标阅读顺序（01 原料…09 分工），每个环节第一个子节点=「环节职责」+一句话原子。
- **命题化规则（09-04 晚立，栗子批评「多轮往返/逐项受质疑」式标签后）**：理解的最小单位=**命题**不是名词——兄弟节点不是并列标签，而是同一句话的下一步；**每条根到叶路径连读必须成立完整命题**（路径连读测试=逻辑性的可操作判据）；名词节点没有内涵子节点（定义/机制/例子/数字）就删。语料教训：**结论备忘录单独撑不起理解**——语料必须带依赖闭包（如核心定义=C18+A-v2 画像+C-v3 论证+C-v4 实验）。
- **术语自举规则（09-04 晚立，栗子用「内核插件已定」例子击穿后定）**：**术语必须先定义、后使用**——图的第一支应为「词汇层」：每个核心术语用日常白话定义（定义链必须最终落到生活用语，链条上不许引用未定义术语）+一个实例子节点；后续分支才有资格使用这些词。同级标题字数不设硬限制（2-7 字为软偏好，怎么表达合理怎么来——09-04 晚栗子撤销 7 字硬检查）。
- **例子节点规则（09-04 深夜定，栗子纠正过一次理解错误）**：「比如/例子/成员例」**单独占一层，例子内容是它的子节点**——例子内容不得与定义等其他内容混排同层。**术语日常化**：抽象术语必须先日常化再用（示范：五种语义的论证=先讲「AI 每轮三步：看信息/做决策/出动作，外加拍板权」，再逐一绑上去——不许直接甩「信息集/决策策略」这类理论词）。
- **标题字数（09-04 深夜终审版，栗子重申「之前定下来的标准不能动」）**：**2-7 字硬限**（check_titles 机器强制，禁逗号顿号句号等标点）；**同级同长排比 ≥4 个出警告**（枚举名单可豁免，不阻断）。**意思装不下 7 字的正确手法=拆成父子命题链**（一句话拆成两三层，每层 ≤7 字），绝不拉长标题。教训：09-04 深夜我两次擅改字数标准（先 2-9 后微命题 6-15）均被打回——**改标准必须栗子点头，动手前先读本条**。
- **验收四条（冷读者测试，每张图交付前过）**：①每个分支列「冷读者会问的问题」清单，每问 2 跳内有答案节点；②路径连读抽查成句；③无裸名词；④信息量对账（源文件信息句 100% 入图或显式留白）。
- **覆盖清单（09-04 定）**：交付导图时必须附覆盖清单——入了哪些资产、哪些留白及原因；「只看导图理解项目全部」是 CM 图的目标态。
- **闭包铁律（09-05 栗子定调，全程认可并升级为验收线）**：**任何不了解导图所讲内容的正常人，只看这张图就能理解所有东西**——所有内容必须全部在图内闭包，不依赖图外文档补链。
- **一口气规则（09-05 栗子明示）**：做导图不许一批两批地挤牙膏——**接到导图任务就一口气推进到最终形态**；内容大可以开目标模式长跑，但不许中途交「阶段性版本」当交付。多批 merge 叠加正是本图结构烂掉的根因（同题节点 3 份、问答堆 17 个），教训已实证。
- **同级分类刀纪律（09-05 栗子立，对 09-04「每级兄弟同一把分类刀」的加码与判例）**：可以接受同一节点下同级主题数量多，**但前提=它们真的只能同级**——同一把分类刀切出来的（穷尽+互斥）。两类违规都算病：①同级但不是同一把刀（实为隶属于不同主题的同级主题被硬拉平）；②根本不该同级（不同级的主题被压平到一层）。**同一层动辄十几二十个标题还互相没什么逻辑性=结构有问题**，判例：全景图 27 个一级分支混了流程轴/问答轴/制度轴/实例轴四种刀；「这图讲什么」下 17 个子节点是「一句话×3 份+区别×3 份+立项散件」的批merge堆砌。修法=每层明确分类轴+主题分组收拢+去重。
- **问题族完备性（09-05 栗子「为什么不微调」批评定立）**：回答「为什么选 X 不选 Y」时，**备选路线族必须先列全再逐个否**——改模型(微调)/模型内触发/换或自建框架/买现成产品…要么全出现在同一层，要么全不出现；只出现一个=假穷尽。且**不属于该族的问题（如「为什么需要新项目」）不许混进来**，归它自己的族。冷读者不知道「微调是啥、对象是什么」=路线节点必须带就地白话定义（改模型即微调→拿你的数据再训练模型）。
- **主张节点=论证链（09-05 栗子「你自己看看这是一句话吗」批评定立）**：标题叫「一句话」的节点=一句主张+一条精炼支撑链（每步一个命题+至多一个依据），禁把多批版本的同义命题平铺成十个子节点（「数据不是能力」与「提炼才是关键」混排=病）。
- **对比同级必须同构（09-05 定）**：「和A比/和B比」型兄弟每项同结构（对象是什么/它缺什么/强在哪）；比较组内禁混入「为什么不用X」式问句节点（那是路线族的成员）。
- **术语自举=阅读顺序硬约束（09-05 升级为机器检查）**：**词汇层必须是图的第一支**；任何术语的首次出现不得早于其定义节点（先序遍历序）；可在使用处就地定义（定义节点注册进 TERMS 白名单）。构建器 `term_order_check` 全图强制，违规即拒绝出图。
- **机器防线四件套（09-05 落地进 build_cm_closure，永久运行）**：①`term_order_check` 术语先定义后使用（违规=阻断）；②`near_dup_report` 同父兄弟子题重叠≥50% 警告（同构表格为预期噪音，真重复用它抓）；③`MERGE_FAMILIES` 已知重复家族按规范名合并+`UNION_TITLES` 同支同名节点最浅层并集（修 batch 叠加的历史病）；④扇出闸门 ≤13+同父同题 dedup（原有）。改动数据文件后重建必须全绿。
- **2-7 字铁律机器强制（09-05 第五轮栗子重申「不允许违反」）**：`check_title_len` 全图阻断——CJK 每字算 1、连续 ASCII 串算 1 单位；超 7 拆父子命题链，1 字改两字词。豁免=纯 ASCII 标题（代号/行号/产品名，可读性由黑话闸管）。批量压缩手法沉淀：①「为什么X」超长→「为何X」/「X」命题化/「X缘由」；②虚词压缩（必须→须、需要→须、的→去）；③链式改名必须一步到终值（改名映射不迭代，中间值会漏）。RENAME_MAP=cm_rename_map.py（~1400 条），构建时先应用再对账。
- **黑话闸（09-05 第五轮）**：整标题为纯 ASCII 的独立黑话标签=阻断（openlist/failvisible 即此类的实锤，已改「开放清单」「故障可见」）；中文标题内嵌技术词由词汇层与上下文负责。词汇层新增「黑话白话」页（token/deny/wwcd/canary/runner/audit/hash/PII/imports/superseded/AUC/CI 各带白话定义+比如）。
- **归属优先于形式（09-05 第五轮栗子批评「为什么叫蒸馏为何在命名辨析」）**：内容挂在它**服务/解释的对象**名下，禁止按表面形式归堆（都叫「为什么叫X」不等于同类）。已实现 `NAMING_BELONGS`：命名辨析组解散，「为什么叫X」机械分发进 X 词条当孩子。
- **叙事序（09-05 第五轮栗子定调）**：导图按上→下左→右阅读，兄弟顺序必须按冷读者认知顺序排（是什么→为什么→怎么做→实例），不是随意陈列；组内排序由 PLANS 计划表顺序负责，验收时按路径连读抽查。

- **QA 机器防线二代（09-05 冷读者 pass 后沉淀，模块=`workspace/default/mindmap_qa.py`，通用可复用）**：旧五道闸（禁标点/术语序/字数/黑话/扇出）之后追加六检，每检都由一次真实返工沉淀——①**链条改名**（RENAME_MAP 的 value 不得再是 key；映射不迭代，链式写法静默漏改，实锤=当前状态查询归a→查状态归a→查状态归事实只走一步）【阻断】②**家族 canon 毒化**（MERGE_FAMILIES 的 fam[0] 必须是终值标题；用改名前标题当 canon 会经 FAMILY_CANON 把改名后标题反向解析回不存在的旧标题，take() 静默返回 None→「未被计划覆盖」远端报错；同题跨支的家族会毒化另一支的引用，只能删不能留）【阻断】③**字母码**（1-3 位纯字母 run 且前后不贴数字=示众；可蒸出af 类混合码漏过黑话闸；字母+数字代号 F2/R14 与注册缩写豁免）④**变体兄弟**（同父按**节点身份**分组——按父标题分组会把跨支同题的远房表亲误判成兄弟【实锤假阳性】；字符多重集相似度≥0.75 示众；数字序数同框（PIPL第四条×第六条）与豁免台账（正交两半/互补命题等，须带理由记录）放行）⑤**机械包装组**（主体/明细N=批合并脚手架残留，栗子判「无逻辑」，全图清零）⑥**导览缺失**（每支首子节点=本支讲什么+白话孩子）。阻断级不过不出图；报告级必须逐条分诊写进覆盖清单，禁静默忽略。`python mindmap_qa.py`=自测（每个坏例子都是返工标本）
- **QA 分诊纪律（09-05 首轮实跑沉淀）**：报告不是噪音是工单——首轮报告抓出 68 对变体+57 处字母码，全部逐条处置（改名统一/家族合并/豁免台账），当前 CM 图=报告 0 项。写豁免台账必须带理由（如 一源蒸多种资产×一资产多源可蒸=正交两半、上层否决下层×下层不否决上层=互补命题、感知日志未当料×首当料=出处相抵存疑待栗子裁）
- **家族合并不动点（09-05 实锤）**：union_within_branch/dissolve_naming 等「重组后再拼兄弟」的步骤会把变体兄弟重新拼到同父，家族合并必须在每次重组后再跑（restructure 里已加两次不动点调用）；新写重组步骤时同理
- **改数据双份同步纪律**：同题节点常有多份数据定义（如 首批登记七条 在 t21/u8），改一处必须先 grep 全部同名定义同步改，否则 dedup 并集会留下变体残渣
- **报告文件时效**：QA/字数报告只在非空时落盘会留旧文件误导，要么永远覆写（现行做法）要么先删
- **交付前机器检查链（任何导图）**：构建五道闸+QA 六检全绿 → `xmind validate` 0 错 → 抽查路径连读 → 覆盖清单（含 QA 分诊台账与留白及原因）
