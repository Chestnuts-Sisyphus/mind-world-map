# 更新协议（CM 图 = 推进标准的时代，图随主体状态更新的唯一合法路径）

> 2026-09-05 作者定调：此后以 CM 的思维导图为标准推进 CM。图从「交付物」升格为「状态单一来源」，
> 更新路径本身就是关键基础设施。本协议与 `xmind-style-baseline`、`pitfalls.md` 同级强制。

## 第零条：图是构建产物，不是手编文件

- **唯一合法的更新路径 = 改数据文件 → `python build_cm_closure.py`。禁止手改 xmind**。
- 图的每个字节都是 `cm_data_*.py + cm_restructure.py` 的确定性函数：同数据必出同图（幂等性已验证，
  连续两次构建第二次自动报「无更新」）。手改图 = 下次构建即被覆盖 = 白改 + 破坏对账。

## 触发时机（什么时候必须更新图）

1. 一把研究刀冻结（A/B/C/D/E/V 线产出定稿）
2. 作者重大拍板（立项/裁决/标准变更）
3. 某支事实变化（新增实锤、事故、制度调整）
4. 至少每次交付/验收节点做一次对账：**源信息 100% 入图或显式留白**（验收四条之四）
- 更新责任 = 做该刀/该拍板的 agent，收尾动作里必须包含图更新，不是「下次再说」。

## 更新六步（每步有机器或流程防线）

1. **归类优先（09-06 铁律，先于落盘）**：骨架=主体（导图总定义：导图=针对一个主体的穷尽延伸，
   作者 09-06）的第一层延伸维度；新内容先按骨架职责找既有支/既有类目落位——
   新术语必须挂在正文首用处并带白话定义（首现即释）；只有全骨架都容不下才允许动骨架，
   且必须说明收拢预案（哪两支合并腾位）。禁新开词典支、禁新开平行类目、禁为单条内容立类。
1. **落盘**：新内容写进对应支的 cm_data 文件（大更新开新 cm_data_zN.py）。
   - 新概念词直接写【定义】X 标记节点（词表自举，无注册表）；数字成绩带对象与口径孩子
   - 标题按终值写（2-7 字、禁标点、术语先定义后用、问句形式做辨析、无字母码、无占位符）
   - 同题节点有多份定义时，先 grep 全部同名位置同步改（双份同步纪律）
   - 压缩值装不下就展开命题链（主权卡三链是范本），不许造密码词
2. **改名对账**：动既有标题只走 RENAME_MAP，一步到终值（链条检查会拦）；连带引用
   （PLANS 引用名、家族成员名、豁免台账）一并核对。
3. **结构对账**：新增 L2 级节点必须挂进对应 PLANS 计划表（覆盖断言会拦「未被计划覆盖」）；
   深层内容不用挂表。
4. **构建**：`python build_cm_closure.py`。构建器自动完成：一代闸（禁标点/首现即定义+唯一性+伴随使用/
   词条合同/空壳/三源归约/成绩口径/一级预算/字数/黑话/扇出）→ QA 七检+类目导览+跨支重复 →
   与现版比对（无变化=不动图不备份）→ 时间戳备份到 `<local-workdir>/HERMES/Connectome-backups/`
   → 生成 `diff_report.txt`（新增/删除/改名三分类，路径级）→ 追加 `build_history.jsonl` 台账。
5. **分诊与复核**：qa_report.txt 逐条处置（改名统一/家族合并/带理由进豁免台账）；diff_report.txt
   人工过目改动面——新增了什么、删了什么、改了什么名，确认无误才算更新完成。
6. **交付**：validate 0 错 + 报告 0 项（或台账清零）+ 覆盖清单（含本次 diff 摘要与留白及原因）。

## 防倒退的三道保险

1. **全树闸门**：每次构建的闸门和 QA 都扫全图而非增量——旧内容违新标准同样被拦，标准只紧不松。
2. **对账被动化（09-06 深夜补条）**：账本里每次真实更新（增/删/改名>0）必须有一份覆盖其时间的
   `workspace/default/coverage/coverage_*.md`（首行「覆盖至: <账本时间>」+ 源→图映射 + 留白），
   构建器每次扫描——缺失即报告「覆盖清单待落盘」，补齐自动消除。源枚举的完备性靠
   "来了的没对账会现形"兜住，不靠任何人记得。
3. **时间戳备份**：每次真实更新自动留旧版（Connectome-backups/），任何一次更新可整版回滚；
   固定名 .bak0904 是流水线启用前的原始快照，永久保留。
3. **构建台账**：build_history.jsonl 逐次记录时间/节点数/QA 项数/增删改数——图的演化史可审计，
   「哪次更新引入的问题」永远可溯。

## 冷读者叙事三合同（09-06 作者实锤后设立，与黑话名单同级强制）

- 起因：作者抓出三连病——「词表→六类分类法」标签释标签、「背题→背题致失效」循环定义、
  「为什么叫C18→第18号资产」在读者从未见过 C18 的位置讨论命名（词汇层前置词典=解释脱离叙事）。
  并点名二级分类冗杂臃肿：分类层只增不减（CM 一度 27 支、二号机 13 支）。
- **首现即释**：注册术语第一次实质出现（先序）2 跳内必须有定义节点；命名讨论只能出现在
  术语被介绍之后（肯定式「为什么叫X/为什么有X」须先介绍，「为什么不叫X」豁免——X 是被否的备选名）。
  机器闸=check_term_locality（构建阻断）。CM 的落地=词汇层整体解散，词条经 REHOME 台账搬回
  正文首用处（蒸馏→统一蒸馏工艺、点单→06 点单、白名单→私聊规则……）。
- **词条合同**：定义=白话（是啥+干嘛用，可带 比如），禁复述术语、禁黑话释黑话、禁未接地代号。
  机器闸=check_vocab_closure（复述式定义阻断）。
- **类目合同**：抽象类目首子=「本块讲什么」白话；名即内容的组进 GUIDE_EXEMPT 台账带理由。
  **一级预算**：root 直系 ≤9（check_top_budget），二级分类收敛靠合并。
- 落点技巧（实锤教训）：词条 A 的孩子若提到词条 B，B 的定义必须就在 2 跳内——CM 的 内核/资产
  词条因此挂进 插件/蒸馏 词条名下，而不是兄弟组；扫描工具=diag_term_body.py（首用路径诊断）。

## 事故黑话名单（INCIDENT_TERMS，09-05 作者实锤后设立）

- 起因：灾难性遗忘风险/自建框架要养runner 两个密码标题裸奔出图，五道闸+QA 六检全绿仍然漏——
  术语注册制是 opt-in，没人注册的词机器不管；黑话闸只查整题纯 ASCII，混排放行。
- 机制：`cm_restructure.INCIDENT_TERMS` 名单只进不出。冷读者（作者或自查）每抓到一个读不懂的
  术语/黑话 → 进名单 → 注册 TERMS + 首用处就地展开（子节点白话），接地闸阻断不接地的重建。
- 混排 ASCII 同日焊死：标题里任何英文串必须已注册、或属「数字尾巴代号/纯大写缩写」两类，
  其余一律阻断逼一次有意识的分诊（放行清单=ALLOWED_EXTRA，放行≠已接地）。
- 判断口诀不变：**标题是句子不是密码**。名单是机器替人盯梢，冷读抽查仍是最后一道人网。

## 已知禁区（踩过的坑，更新时尤其容易复发）

- 禁一批批挤牙膏：更新也一口气到终形态，同题内容禁多批叠加（CM 图结构烂掉的根因）
- 禁改标准不问作者：2-7 字铁律等改标准必须先点头
- 禁造密码词：字母码、占位符（X/N）、超压缩值一律中文化或展开命题链
- 禁动「稳定区」顺手重构：最小改动，更新只动该动的地方（diff 报告就是核对工具）
